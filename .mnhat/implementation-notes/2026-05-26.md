### OTA hash contract fix

- **Type:** bug-fix
- **Status:** done
- **Commit:** `none — worktree has unrelated in-flight changes outside this bug-fix`
- **Risk:** medium
- **Files Changed:** `server/api/src/services/ota.js`, `server/api/test/device-ota-route.test.js`, `docs/API_REFERENCE.md`, `docs/MQTT_PROTOCOL.md`
- **Verification:** `cd server/api && node --test test/device-ota-route.test.js --test-name-pattern "appended ESP image digest"`, `cd server/api && npm test -- test/device-ota-route.test.js test/emqx-bridge-ota-rule.test.js`

**Why:** Runtime OTA failed with `SHA256 mismatch` because the API was publishing `sha256sum` of the whole `.bin` artifact while firmware verifies the ESP-IDF app image digest returned by `esp_partition_get_sha256()` when `hash_appended=1`.

**What changed:** The OTA service now detects ESP-IDF app images with an appended simple hash, validates that appended digest against the image payload, and publishes that digest to firmware. Non-ESP artifacts still fall back to full-file SHA-256.

**Tradeoff:** This keeps the OTA payload shape unchanged and matches the current firmware + ESP-IDF contract, but it assumes the current unsigned ESP-IDF image layout; if secure-boot signed artifacts are introduced later, the server-side parser will need to understand signed image trailers too.

### Understand dashboard graph load fix

- **Type:** bug-fix
- **Status:** done
- **Commit:** `none — local knowledge-graph artifact fix only`
- **Risk:** low
- **Files Changed:** `.understand-anything/knowledge-graph.json`, `.mnhat/implementation-notes/2026-05-26.md`
- **Verification:** `rtk proxy node -e "const {validateGraph}=require('/home/nhat/.understand-anything-plugin/packages/core/dist/index.js'); const g=require('./.understand-anything/knowledge-graph.json'); const r=validateGraph(g); console.log(JSON.stringify({success:r.success,fatal:r.fatal,issueCount:r.issues.length,nodeCount:r.data?.nodes.length,edgeCount:r.data?.edges.length}, null, 2));"`

**Why:** The dashboard failed with `Invalid knowledge graph: No valid nodes found in knowledge graph` because every node in the saved graph carried `languageNotes: {}`, while the plugin schema only accepts `languageNotes` as a string or omitted.

**What changed:** Removed `languageNotes` from all saved graph nodes so the current dashboard/core validator can accept the artifact; edge `direction` fields are still auto-corrected at load time by the plugin.
